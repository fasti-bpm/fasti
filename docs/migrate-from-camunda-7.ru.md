# Переход с Camunda 7 на Fasti BPM

Fasti BPM построена на Camunda 7 Community Edition 7.24.0 и совместима с базами данных
Camunda 7. Это независимый проект, не связанный с Camunda Services GmbH.

<a id="summary"></a>

## Краткий обзор

Если вы используете Camunda 7 **7.24** (Run, образ контейнера, стартер Spring Boot, Tomcat или
WildFly), Fasti работает с **той же базой данных без изменения её схемы**: она использует схему 7.24
без изменений и не добавляет собственных таблиц, столбцов или версий схемы. Вы можете заменить
старые узлы, запустить Fasti параллельно с ними и вернуться к Camunda 7.24 (см.
[Возврат](#rollback-to-camunda-724) и протестированные базы данных в разделе [Ограничения](#limits)).

Базы данных Camunda 7.23 и более ранних версий необходимо сначала обновить до 7.24 с помощью SQL-скриптов (см.
[Более ранние версии](#older-versions-717723)). Fasti никогда не обновляет схему самостоятельно; при обнаружении
старой схемы она отказывается запускаться и указывает скрипты, которые необходимо выполнить.

<a id="steps-container-image"></a>

## Порядок действий (образ контейнера)

1. **Создайте резервную копию базы данных.** Ни один из приведённых ниже шагов не изменяет схему, но резервная копия
   обязательна перед любыми изменениями в рабочей системе.
2. **Проверьте версию схемы:** `select VERSION_ from ACT_GE_SCHEMA_LOG` — наибольшее значение
   должно быть `7.24.x`.
3. **Запишите текущую конфигурацию** старого узла: переменные `DB_*`, уровень истории
   (`camunda.bpm.history-level`, `ACT_GE_PROPERTY.historyLevel`), аутентификацию REST
   (`camunda.bpm.run.auth.enabled`), авторизацию (`camunda.bpm.authorization.enabled`),
   плагины, LDAP/SSO, часовой пояс JVM, хеширование паролей (`passwordEncryptor`, `saltGenerator`),
   префикс таблиц/схему.
4. **Загрузите образ** `fastidev/fasti-bpm:1.1.0` (или соберите его из исходного кода, как описано в
   [distro/docker/README.md](../distro/docker/README.md)).
5. **Запустите Fasti с теми же переменными `DB_*`** (и тем же значением `TZ`). В отличие от Camunda Run,
   образ Fasti **по умолчанию требует аутентификацию REST и применяет проверки авторизации**: учётные записи
   базы данных продолжают работать, но каждый REST-клиент должен передавать учётные данные Basic или токен Bearer,
   а пользователям вне `camunda-admin` необходимы разрешения в `ACT_RU_AUTHORIZATION` (см. раздел «Безопасность по
   умолчанию» в [distro/docker/README.md](../distro/docker/README.md)).
   `FASTI_INSECURE_DEMO=true` предназначено только для демонстраций. Fasti записывает в журнал
   `ENGINE-03115 Database schema version 7.24.0 matches this engine.`
6. **Проверьте:** войдите в `/fasti/` с существующей учётной записью; убедитесь, что фильтры, задачи, экземпляры и история на месте; вызовите `GET /engine-rest/task` (с учётными данными Basic) и `GET /actuator/health/readiness`.
7. **Перенаправьте трафик** (балансировщик нагрузки, DNS) на Fasti; остановите старые узлы или оставьте их работающими (см.
   [Совместная работа](#mixed-operation-with-camunda-7-nodes)).

Стартер Spring Boot / Tomcat / WildFly: замените артефакты `org.camunda.bpm:camunda-*`
соответствующими артефактами `dev.fasti.platform:fasti-*`, сохранив `camunda.bpm.*`, `bpm-platform.xml` и
пакеты `org.camunda.bpm.*`. Не оставляйте JAR-файлы обоих движков в classpath: в этом случае Fasti откажется запускаться (об ограничениях этой проверки см. раздел «Проверка при запуске» в
[embedding.ru.md](embedding.ru.md#startup-check)).

> **Стартер Spring Boot:** Fasti работает на **Spring Boot 4.1** и требует **Java 17 или новее**.
> Приложения на стартере Camunda 7.24 (Spring Boot 3.5) должны перейти на Spring Boot 4.1 и
> Java 17+ одновременно с заменой артефактов. См.
> [embedding.ru.md](embedding.ru.md#what-is-different-from-camunda-7240-ce) и
> [CHANGELOG](../CHANGELOG.md#changed).

<a id="tomcat-and-wildfly-distributions"></a>

## Дистрибутивы Tomcat и WildFly

> **Обязательно при переходе на базу данных Camunda Run** (или сервера, процессы которого были
> развёрнуты через REST API): в дистрибутивах Tomcat и WildFly сохраняется
> `jobExecutorDeploymentAware=true`, как в Camunda 7. Задания (таймеры, асинхронные продолжения, повторные попытки)
> развёртываний, не зарегистрированных на узле, **не выполняются, и сообщения об ошибке не выдаются**.
> Перед запуском установите `<property name="jobExecutorDeploymentAware">false</property>` в
> `conf/bpm-platform.xml` (Tomcat) или в свойствах движка в `standalone.xml` (WildFly).
> Оставьте `true`, если на других узлах работают приложения процессов с собственными Java-классами (см.
> [Совместная работа](#mixed-operation-with-camunda-7-nodes)).

По сравнению с дистрибутивами Tomcat/WildFly для Camunda 7.24:

- **REST API требует аутентификацию** (нарушает совместимость). Для `/engine-rest` включён фильтр `camunda-auth`
  (HTTP Basic): каждый REST-клиент должен передавать имя и пароль пользователя движка; иначе он получает 401; открытым остаётся только список движков (`/engine`).
  Перед переходом настройте учётные данные в REST-клиентах, обработчиках внешних задач и скриптах, которые вызывают REST
  API анонимно. Токены Bearer OpenID Connect (`fasti-oidc.properties`,
  `fasti.security.oidc.rest.bearer-enabled=true`) также поддерживаются: запросам с действительным токеном пароль не нужен. Чтобы отключить аутентификацию (**не рекомендуется**), удалите
  фильтр `camunda-auth` и его `filter-mapping` из `WEB-INF/web.xml` WAR-файла `engine-rest`.
- **Нет пользователей по умолчанию** (нарушает совместимость). Пример обработки счетов больше не развёртывается, поэтому он не
  создаёт `demo/demo` (администратор), `john`, `mary` и `peter`; его WAR-файл находится в
  `examples/camunda-invoice.war`; чтобы опробовать пример, скопируйте его в `webapps/` (Tomcat) или
  `standalone/deployments/` (WildFly). Для пустой базы данных откройте `/fasti/`
  и создайте первого администратора на странице первоначальной настройки; для базы данных Camunda 7 используйте
  существующие учётные записи.
- **Классические Cockpit, Tasklist, Admin и Welcome недоступны** (нарушает совместимость), как и в
  образе: их страницы и закладки ведут в соответствующий раздел нового интерфейса, а запросы их файлов возвращают 404. Чтобы временно включить их снова (возможность устарела и будет удалена), используйте один из следующих параметров:
  `-Dfasti.webapp.classic.enabled=true` в `CATALINA_OPTS` (Tomcat) или `JAVA_OPTS` (WildFly),
  переменную окружения `FASTI_CLASSIC_WEBAPPS=true` или параметр контекста
  `fasti.webapp.classic.enabled` в `WEB-INF/web.xml` веб-приложения.

<a id="what-is-identical"></a>

## Что остаётся прежним

- Схема и строки `ACT_GE_PROPERTY`/`ACT_GE_SCHEMA_LOG` (Fasti не добавляет строку версии),
  идентификатор установки, генерация идентификаторов (`StrongUuidGenerator` в Run/Spring Boot,
  стандартный для движка `DbIdGenerator`).
- Пароли: SHA-512 с 16-байтовой солью, как в Camunda 7; существующие пользователи могут входить в систему, а
  пароли, изменённые в Fasti, работают в Camunda 7.
- REST API по адресу `/engine-rest`: те же конечные точки, параметры и полезные данные плюс
  дополнительные конечные точки (аутентификация и некоторые коды состояния отличаются, см. [Что отличается](#what-differs)), внешние задачи
  (`fetchAndLock`, длительный опрос), клиенты Java и JS, `JSESSIONID`, `XSRF-TOKEN`/`X-XSRF-TOKEN`, свойства `camunda.bpm.*`,
  пространство имён BPMN `camunda:`.
- Фильтры классического Tasklist (`color`, `description`, `priority`, `refresh`, `variables`,
  `showUndefinedVariable`) читаются и записываются новым Tasklist в том же формате.

<a id="what-differs"></a>

## Что отличается

- Веб-приложения расположены по адресу `/fasti/app/...`; `/camunda/...` перенаправляет туда (301/308). Если ваш прокси предоставляет доступ только к `/camunda`, предоставьте доступ также к `/fasti` или установите `FASTI_WEBAPP_PATH=/camunda`. По корневому адресу
  открывается новое веб-приложение (`fasti.webapp.default-app: welcome` возвращает Welcome, кроме
  образа, в котором классические приложения отключены).
- **Нарушение совместимости, образ контейнера:** классические Cockpit, Tasklist, Admin и Welcome
  недоступны, поскольку поддержка AngularJS 1.8.2 и Bootstrap 3 завершена. Их страницы и закладки,
  в том числе по адресам внутри `/camunda/app/`, перенаправляют в соответствующий раздел нового веб-интерфейса (`#/cockpit`,
  `#/tasklist`, `#/admin`); запросы их файлов возвращают 404. Переведите пользователей на новый веб-интерфейс;
  `FASTI_CLASSIC_WEBAPPS=true` снова включает классические приложения на переходный период с
  предупреждением. Tomcat и WildFly также не предоставляют к ним доступ (см.
  [Дистрибутивы Tomcat и WildFly](#tomcat-and-wildfly-distributions)). ZIP-архив Run и
  стартер Spring Boot пока предоставляют к ним доступ, но они устарели и будут удалены в одном из последующих
  выпусков (`fasti.webapp.classic.enabled: false` отключает их заранее).
- При использовании старой схемы Fasti отказывается запускаться с `ENGINE-03111`, вместо того чтобы завершиться ошибкой позднее
  (`FASTI_SCHEMA_VERSION_CHECK=warn` позволяет всё же запустить её).
- Выражения в запросах и фильтрах ограничены списком разрешённых элементов (функции даты, текущий
  пользователь); пользовательские компоненты или функции, используемые в фильтрах, необходимо объявить в свойствах конфигурации движка
  `allowedExpressionFunctionsInQueries`, `allowedExpressionBeansInQueries` и
  `allowedExpressionPropertiesInQueries`.
- Поведение REST API: в контейнерном образе и в дистрибутивах Tomcat и WildFly каждый запрос,
  кроме списка движков (`/engine`), требует учётные данные Basic или bearer-токен, поэтому
  REST-клиенты и воркеры внешних задач нужно настроить на их отправку (их код не меняется). Во
  всех дистрибутивах выражения в запросах вне списка разрешённых отклоняются с `400`; чтение или
  изменение вложений и комментариев задач без прав получает ответ `403` (при включённых проверках
  авторизации); некоторые некорректные запросы, на которые раньше отвечали `500`, теперь получают
  `400` (неразбираемые ресурсы развёртывания, переменные в запрещённом формате сериализации Java,
  параметры запроса неверного типа, пароли, нарушающие политику паролей). См.
  [Differences from Camunda 7](api/README.md#differences-from-camunda-7) (на английском).
- Настройки образа по умолчанию: обновление схемы `false` (`FASTI_DB_SCHEMA_UPDATE=true` для новой базы данных); нет
  демонстрационного пользователя, примера обработки счетов и фильтра «Все задачи»; CORS отключён (`FASTI_CORS_ALLOWED_ORIGINS=*`
  включает его); добавлен `/actuator/health`; файлы расположены внутри `/fasti` (файлы, смонтированные в
  `/camunda/configuration`, также читаются); нет `--swaggerui`.
- OAuth2/OIDC: `camunda-admin` в утверждении о группах больше не предоставляет права администратора само по себе
  (`fasti.security.oidc.groups.admin`); `group-name-delimiter` — буквальный текст, а не регулярное выражение;
  для выхода требуется POST-запрос с того же источника.
- Новый Tasklist: фильтр без `refresh` обновляется автоматически.
- JAR-файл Run называется `fasti-bpm-run-core.jar`.
- Исправления безопасности по сравнению с 7.24.0 (авторизация для вложений/комментариев, первоначальная настройка, ...) могут привести к тому, что некоторые ранее успешные вызовы будут возвращать 403; см. разделы *Security* в [CHANGELOG](../CHANGELOG.md) и <https://fasti.dev/security>.

<a id="rollback-to-camunda-724"></a>

## Возврат к Camunda 7.24

Остановите Fasti и снова запустите узлы Camunda 7.24 с той же базой данных. Все действия, выполненные в
Fasti, будут там видны. Что останется: строки `fasti.prefs.*` в `ACT_ID_INFO` (настройки
нового веб-интерфейса, игнорируемые Camunda 7) и `refresh: true` в фильтрах, сохранённых новым Tasklist, где
этого свойства ранее не было. Развёрнутые процессы, использующие возможности, доступные только в Fasti, не работают в Camunda 7.

<a id="mixed-operation-with-camunda-7-nodes"></a>

## Совместная работа с узлами Camunda 7

Fasti и Camunda 7.24 могут одновременно работать с одной базой данных (проверено: обе системы видят данные
друг друга, а задания выполняются на любом из узлов). Требования:

- **одинаковый уровень истории** (образ использует сохранённый уровень), **одинаковый часовой пояс JVM**,
  одинаковые настройки паролей и префикс таблиц;
- **исполнитель заданий:** по умолчанию Fasti (образ, Run, Spring Boot) подхватывает задания всех развёртываний, как и Run.
  В дистрибутивах Tomcat и WildFly по умолчанию задано `jobExecutorDeploymentAware=true` (как в Camunda
  7): задания (таймеры, асинхронные продолжения, повторные попытки) развёртываний, не зарегистрированных на этом
  узле, включая развёртывания, выполненные через Run или REST до последнего перезапуска, **не
  выполняются**; при переходе на базу данных Run установите значение `false` в `conf/bpm-platform.xml`
  (Tomcat) или `standalone.xml` (WildFly). Если на старых узлах работают приложения процессов с классами, которых нет в Fasti (`JavaDelegate`, слушатели, компоненты),
  Fasti будет подхватывать их задания, которые затем будут завершаться ошибками и создавать инциденты. В таком случае установите
  `FASTI_JOB_EXECUTOR_ENABLED=false` в Fasti или настройте **каждый** узел на учёт развёртываний (исполнитель
  заданий узла выполняет только задания развёртываний, зарегистрированных на этом узле; развёртывание, выполненное через
  REST, регистрируется только на принявшем его узле и только до перезапуска). Синхронные REST-вызовы (завершение задачи,
  запуск экземпляра) по-прежнему выполняют делегаты на узле, который их принимает, — не направляйте такие
  процессы в Fasti;
- **балансировщик нагрузки:** привязка сессий к узлам для веб-приложений; REST-вызовам с аутентификацией Basic она не нужна;
- классические веб-приложения (на узлах Camunda 7 или Fasti с
  `FASTI_CLASSIC_WEBAPPS=true`) и новое приложение используют общие фильтры и пользователей.

<a id="older-versions-717723"></a>

## Более ранние версии (7.17–7.23)

Создайте резервную копию; последовательно выполните `sql/upgrade/<db>_engine_<from>_to_<to>.sql` вплоть до 7.24, включая
ещё не выполненные скрипты исправлений для текущей минорной версии (поставляются в `configuration/sql/upgrade`, в
образе — `/fasti/configuration/sql/upgrade`); убедитесь, что `ACT_GE_SCHEMA_LOG` содержит `7.24.0`;
запустите Fasti. Пример для 7.22 → 7.24: `postgres_engine_7.22_to_7.23.sql`, затем
`postgres_engine_7.23_to_7.24.sql`. Узлы Camunda старше 7.24 не должны продолжать работу с
обновлённой схемой, кроме случаев, предусмотренных правилами последовательного обновления Camunda (только на одну минорную версию, при этом
старые узлы не должны использовать новые возможности).

<a id="performance"></a>

## Производительность

Образ больше не использует значения Camunda Run по умолчанию для исполнителя заданий и пула
соединений (до Fasti 1.1 использовал): он работает с 10 потоками заданий, очередью на 10 и 10
заданиями за одну выборку (Camunda Run: основных потоков 3, максимум 10, очередь 3, 3 за выборку) и
пулом до 20 соединений, из которых 10 остаются открытыми в простое (Camunda Run: 10). Рассчитывайте
лимит соединений базы данных на сумму пулов всех узлов, включая узлы Camunda 7 ([настройка во время
работы](tuning-runtime.md), на английском). Если вы настраивали пул соединений или исполнитель
заданий в прежней установке Camunda 7, перенесите эти значения (`FASTI_DB_CONN_MAXACTIVE`,
`FASTI_DB_CONN_MINIDLE`, `CAMUNDA_BPM_JOB_EXECUTION_*`); дополнительные рекомендации приведены в
`distro/docker/README.md`, в разделе «Настройка производительности». Fasti никогда сам не меняет
индексы схемы; для больших баз данных он поставляет дополнительные индексы в виде скриптов, которые
запускает администратор
(`/fasti/configuration/sql/optional/<database>_fasti_perf_indexes_create.sql`, см.
[performance.md](performance.md)); они безопасны рядом с узлами Camunda 7.24 и удаляются
соответствующим `_drop.sql`.

<a id="limits"></a>

## Ограничения

- Поддерживается только схема 7.24 Community Edition; схемы исправлений Enterprise не тестировались.
- Проверено с образом контейнера (Camunda Run 7.24.0 создаёт и заполняет базу данных → Fasti
  начинает её использовать → возврат к Run → одновременная работа обеих систем):

  | База данных | Драйвер | Переход | Возврат | Совместная работа | Обновление 7.23 → 7.24 |
  |---|---|---|---|---|---|
  | PostgreSQL 16 | в комплекте | успешно | успешно | успешно | не проверено |
